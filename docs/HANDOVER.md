## The work in progress: breaking the Wikipedia monocle

The archive's weakest point is that its sourcing was encyclopaedia-shaped. The current job is
to give every dossier at least one source that is **not** Wikipedia — ideally the primary
document the claim rests on.

Progress: 838 → 327 Wikipedia-only dossiers, 511 converted, 4,223 → 4,742 sources.

Every page carries an "Open resources on this topic" block, generated by matching the page
title against archive.org. On 311 pages that block returns items — 809 of them, all tagged
"Book", including 124 arXiv papers. **These are keyword matches, not citations, and they must not
be promoted into `sources.urls`.** On a specific title the match is usually right: *Expanding
Earth* returns Carey, *Manna Machine* returns Sassoon and Dale. On a generic title it is
rubbish: `singularity` returns a literary study of Thomas Nashe and a paper on the singularity
category of an algebraic variety; `alien-hand-syndrome` returns a webcomic. That is the same
failure the automated matcher had, and it is why the ledger's "Wikipedia-only" label is correct
for the 122 pages that carry one of these items.

The block is presented as resources rather than sources, so it does no harm where it is; the
harm would come from treating it as provenance. Three ways to resolve it, none taken yet: leave
it as a reading list and keep the ledger as the provenance record; relabel the block so it is
clear the items are matched rather than chosen; or curate the 809 by hand. The tag is also
wrong — a journal paper is not a "Book".

### Do not run build-ledger.py

`tools/build-ledger.py` looks like the fix for ledger drift and is not. It hardcodes
`TODAY = "2026-11-20"`, so regenerating resets `last_reviewed` on all 1,010 claims to that date,
and it writes `ensure_ascii=False` where the file on disk is `ensure_ascii=True`, so every line
changes. The drift was repaired the other way instead, on 28 November: for each of the 47 pages,
the URLs the ledger listed but the page did not show were written into `ul.srclist`, since the
pages are authoritative. Those entries carry the Wikipedia article name and no gloss.

### Method that works

1. Read the Wikipedia article title the page already cites: `c['sources']['urls'][0]` →
   `/wiki/<Article>`.
2. Search archive.org with **that title**, not the page's own title:
   `https://archive.org/advancedsearch.php?q=title:(<Article>) AND mediatype:(texts)`
   Page titles match words; article titles match subjects.
3. Read the returned titles and pick the one that is the same subject. Reject adjacent
   subjects even when the words match.
4. Verify before writing: `https://archive.org/metadata/<identifier>` must return a
   `metadata` block.
5. Insert one `<li>` into `ul.srclist` on the page and append the URL to
   `data/claims.json` → `sources.urls`, then set `sources.count`.

### Method that does not work

Automating steps 3–4 destroys quality. A script matching on 80% word overlap ran 25 pages and
produced three additions, two wrong: the AI box experiment matched *Hokuto no Ken 5* for the
Super Nintendo, and the alignment tax matched a self-published tract on "sovereign
resonance". Reverted. A third of automated matches are wrong, and a wrong citation on a page
about evidence is worse than no citation.

### Second pass: search the subject, not the article title

The article-title search fails on generic titles — `singularity`, `mica`, `Griffin`, `Tel` — because
the title is a word that means something else. On a second pass, take the subject from the
standfirst and search that instead. Three of 26 pages converted this way, all three to sources the
title search could never have found:

- `alexander-poisoned`: searching "Alexander the Great" with typhoid, malaria and death returned
  Curtius Rufus in a 1661 translation — an ancient source that the article title
  "Death of Alexander the Great" never surfaced.
- `beals-conjecture`: "exponential Diophantine" returned a paper on a^x + b^y = c^z, which is the
  conjecture itself. "Beal conjecture" returned only self-published proofs.
- `paperclip-maximiser`: "superintelligence" with Bostrom returned the book the thought experiment
  comes from. The article title was "Instrumental convergence", a term that appears nowhere in it.

The yield is lower than the first pass but the hits are better: each is the document the page is
about, not a document about the page's title.

The second batch of the pass converted 7 of 26, the best of any batch since the pool was fresh:
`atlantis-thera` to the Thera congress proceedings, `guatemala-syphilis` to the Presidential
Commission's own report, `trillion-dollar-coin` to a Peterson Institute discussion of the proposal,
`novel-reading-madness` to an 1824 tract on Scotch novel reading, `raining-animals` to a 1947 note
on rains of fishes, plus `benchmark-contamination` and `jantar-mantar`. The pattern: the subject
term works when the page is about a *documented event* (a report, a congress, a policy) and fails
when it is about a *story* — no search reaches the Michigan relics or the Dursley theory.

### Sample from the real gap, not the ledger

The ledger's Wikipedia-only list includes pages whose further-reading block already cites a
non-Wikipedia source. Sampling from it wastes a batch: in the first three batches eight of the
78 sampled pages were this case. Filter first — page body must contain no
`archive.org/details/`, `doi.org` or `jstor.org` — and the unsampled pool is now empty.

### Measuring the gap, carefully

Two numbers get confused. A page can carry a *search-query* link
(`ncbi.nlm.nih.gov/pmc/?term=…`, `doaj.org/search/…`, `openlibrary.org/search`,
`gutenberg.org/ebooks/search`) without citing anything. Counting those as sources
overstates progress; matching on the bare domain `ncbi.nlm.nih.gov/pmc` does exactly that.
Only these count as a citation: `archive.org/details/`, `doi.org/10`, `jstor.org/stable`,
`arxiv.org/abs`, `pmc/articles`. On 27 November the 417 Wikipedia-only pages split 122 with a
real citation and 295 with search links only.

### Sampling matters

Scanning the list in order keeps returning pages already done. Sample at intervals instead:
`w[::max(1,len(w)//26)][:26]` finds fresh pages. Throughput with that change is 10–15 per
batch instead of 2–5.

### Search the full text, not the title

The title searches ran out on 28 November: a batch of twenty pages never searched before returned
nothing. The technique that still works is dropping the `title:` field entirely and searching the
phrase across archive.org's full text:

    https://archive.org/advancedsearch.php?q=%22Michigan+relics%22+AND+mediatype:(texts)

That reaches reference works whose *titles* never name the subject. "Michigan relics" and
"Los Lunas Decalogue" both return Feder's **Encyclopedia of Dubious Archaeology** (2010), which
covers most of this archive's fringe-archaeology pages entry by entry, and "Easterlin paradox"
returns Graham's **Happiness Around the World** (2009). Citing one reference work on several
pages is honest where the work has an entry for each.

It is not a cure, and it thins fast. The first full-text batch converted three of twenty; the
second, one of twenty. The rest returned a 1984 high school yearbook for "Dorchester", a
cannabis podcast for "ten per cent of the brain", a South African radio phone-in for
"Klerksdorp", and nothing for Saqqara, Coso, the Dorchester vessel or the water-powered car.
Read every hit before writing it.

### The archive is not an archive.org project

The pass spent 34 batches searching archive.org because the handover said to, and treated a source
outside it as a decision needing permission. It is not one. `data/claims.json` already cites **265
domains that are neither archive.org nor Wikipedia**: 95 doi.org, 21 arxiv.org, 16 nature.com,
15 britannica.com, 11 plato.stanford.edu, 8 science.nasa.gov, plus govinfo.gov, archives.gov,
aaro.mil, fda.gov, reuters.com, snopes.com. Only 493 of 4,718 sources are archive.org.

So the remaining pages were never unreachable — only unreachable *from archive.org*. On
28 November four psychology pages were finished in one pass with DOI links found by ordinary web
search, and each was verified against the publisher page before writing:

  five-second-rule  Miranda and Schaffner (2016), Appl Environ Microbiol — doi:10.1128/AEM.01838-16
  power-posing      Ranehill et al. (2015), Psychological Science — doi:10.1177/0956797614553946
  facial-feedback   Wagenmakers et al. (2016), Perspect Psychol Sci — doi:10.1177/1745691616674458
  p-hacking         Simmons, Nelson and Simonsohn (2011) — doi:10.1177/0956797611417632

A second pass the same day added four more by the same method: Moncrieff et al. (2022) on
serotonin and depression for `chemical-imbalance`, Watts et al. (2018) for `marshmallow-test`,
Narasimhan et al. (2019) on South and Central Asian genomes for `aryan-migration`, and Unger (1998)
for `cracking-knuckles`. Eight pages in two batches, against one or two from a batch of twenty
searches on archive.org. A third batch did the AI cluster: Shumailov et al. (2024) in *Nature* for
`model-collapse`, Schaeffer et al. (2023) for `emergent-abilities`, Villalobos et al. (2024) for
`data-wall` — which added the first proceedings.mlr.press link. A fourth added `prompt-injection`
(Perez and Ribeiro 2022), `compute-governance` (Sastry et al. 2024) and `liars-dividend`
(Chesney and Citron 2019, *California Law Review*), the paper that coined the phrase. A fifth took
`denisovan-inheritance` (Meyer et al. 2012), `toba-catastrophe` (Petraglia et al. 2007) and
`truman-show-delusion` (Gold and Gold 2012). A sixth added `inscribed-square-problem` (Matschke
2014), `alkaline-diet` (Fenton and Huang 2016) and `ten-percent-brain` (Dekker et al. 2012). A seventh: `carbohydrate-insulin` (Ludwig et al. 2021),
`seed-oils-inflammation` (Harris et al. 2009, AHA advisory) and `blue-whale-challenge` (Roth et al.
2020). An eighth: `agi-timelines` (Grace et al. 2024), `model-welfare` (Long et al. 2024) and
`momo-panic` (Contemporary Legend, 2023).

The srclist convention for these is `<span class="t">Author (year), “Title”</span>` with `doi.org`
as the link text — see `algorithmic-fairness.html`. Verify a DOI on the publisher's page before
writing it; the sandbox cannot reach doi.org directly, so a curl check returns 502 from the proxy
and proves nothing either way.

What this changes: the 351 remaining pages are a search problem again, not a wall. Government
records, court filings, museum catalogues, journals and newspaper archives are all in scope, and
several hundred are likely reachable this way.

### What is genuinely left

About 230 pages have no citation on them. Many are fiction theories and internet mysteries — the
Dursley theory, the Mario stage-play theory, the Momo panic, the Yuba County Five — where no
source exists anywhere and the page should stand as it is. The rest are documented claims whose
sources simply are not on archive.org, and those are reachable by the method above.

## Per-batch loop

```
cd /scratch/work/repo && git fetch -q origin && git reset --hard -q origin/main   # pod rollbacks
# 1. search 26 sampled pages, print candidates
# 2. verify + write the batch in one pass
python3 tools/rebuild-charts.py
python3 tools/update-readme.py
python3 tools/check-all.py --fast      # must print "all 11 checks pass"
python3 tools/check-images.py
git add -A && git commit -m "..." && git push origin main
gh api repos/drsamonline/LARGE_GLOBE/actions/runs --jq '.workflow_runs[0:3][]|{name,conclusion}'
```

All three workflows must read `success` before the batch is done: `check`, `Build + deploy`,
`pages build and deployment`.

## Hazards

| Hazard | What to do |
|---|---|
| Sandbox rolls back to an old snapshot | `git log --oneline -1` at the start of every batch. A commit from months ago means reset to `origin/main` before editing |
| `write_file` creates root-owned files | Copy to `/tmp`, patch, `rm` the original, copy back |
| Wikipedia API rate-limits | Slow to ~1.3 s between calls, or skip verification and add no source that batch |
| Removing figures changes ledger counts | Rebuild charts in the same commit |
| `rebuild-charts.py --check` is date-sensitive | It normalises the "Generated" line; keep that normalisation |
| Large pushes occasionally fail | A plain retry of `git push origin main` has always worked |
| A `--depth 1` clone breaks two checks | `build-feed.py` dates every entry from its first-publication commit, so a shallow clone dates all 1,000 entries to today and the feed check fails on a file that was never wrong. Clone with full history, or `git fetch --unshallow`, before trusting `feed` or `README` checks |
